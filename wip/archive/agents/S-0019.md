## Decisions

- The planner's seven tasks and four layers are kept as drafted (TH-0029). Layer 1: T-0087, T-0088, and T-0089, which share no path and wait for none. Layer 2: T-0090 and T-0091, each waiting for T-0089's helpers. Layer 3: T-0092, which waits for T-0089's helpers, T-0090's signet step, and T-0088's manifests. Layer 4: T-0093, which names the scripts of T-0087, T-0091, and T-0092 in the block, and `flai check` needs each program to exist.
- Shared services: I recommended on TH-0029 pointing `kluster.config` at `integration/kluster.yaml` (profile `authstar`, the config S-0575 ran over), not adding addons to the root `kluster.yaml`. kluster 1.3.1's README lists no `postgres`, `rabbitmq`, `clickhouse`, or `dex` addon. The operator confirmed it on TH-0029 at 2026-11-09T22:01:44Z. T-0093 points `kluster.config` at `integration/kluster.yaml` and deletes the root `kluster.yaml`. The cost-of-delay question stays the operator's.
- In the default namespace, the deploy first deletes the Deployments and CronJobs that `kubectl apply` did not make, meaning those without the `last-applied-configuration` annotation. These are the profile's `latest` services, and a merge would keep their fields (S-0575's `promote.sh`).
- Signet bundles are pushed with the signet CLI 0.10.3's `bundle push` from a git tree built under `FLAI_KLUSTER_STATE`. S-0575's `storens` is a Go tool over a patched kluster-lib, and this repository does not have it.
- No cluster command is run by me or by a sub-agent (D-0026). Each script is checked with `shellcheck`, `sh -n`, and `KLUSTER_DRY_RUN=1`. Criterion 3 is left to the operator or flai serve.
- Task sub-agents check their scripts with `shellcheck` and dry runs, not with `flai test`. I run `flai test` once per layer (D-0031).
- T-0090 replaced the planned `signet bundle push` from a git tree with `scripts/kluster-signet-push.mjs` over `@bytepunx/signet-client`. The CLI sends no `config_path`, so it cannot write the config every service needs. signet's SyncBundle only adds or updates and never deletes, so pushing one namespace's bundles leaves the others alone. The fresh keys are kept in `FLAI_KLUSTER_STATE/signet-secrets.json`, so a redeploy pushes the same ones.
- I added `signet_connect`, `signet_disconnect`, and `signet_cli` to `lib-kluster.sh` myself, before layer 2, since T-0090 and T-0091 both needed them.
- The deploy passes the RabbitMQ password on stdin, never as an argument. It runs `npm ci` in `tower` when the signet client is missing, as in flai's promotion checkout.
- `integration/README.md` already failed the markdown lint on main, with 6 findings. T-0093 fixed them, since it changes that file.
- Shared paths with other open stories: `integration/README.md` with S-0006 and S-0007, and `design/system/overview.md` with S-0007 and S-0008. S-0019 changed one section of the README and one table row of the overview, and it makes no more changes to either. I said so, settled, on MS-0017 and MS-0018. Every trial merge is clean.
- Criterion 3 is left unticked, and the reason is in the story's Notes.
