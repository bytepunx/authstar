## Decisions

- Plan layers: L1 T-0107 (CA + Secret authstar-tls in both deploys), T-0108 (portcullis.yaml), T-0109 (chronicle sidecar + CA trust) run together: no shared paths, and the contract between T-0107 and T-0109 is the Secret's name and keys (ca.crt, tls.crt, tls.key). L2 T-0110 (all golden-path script changes) waits for all three, since it uses the host, the container, and the Secret. L3 T-0111 (README, I-0007) waits for T-0110. A tower task may join L1 depending on TH-0047.
- TLS front is a sidecar in chronicle's pod with hostAliases, not a CoreDNS rewrite plus a shared front: story namespaces share one kluster, a cluster-wide rewrite maps the host to one namespace only, and editing kube-system's CoreDNS is shared infrastructure. Cost: keep, herald, and web each need their own sidecar when they verify tokens in-cluster (I-0006).
- The sidecar runs chronicle's own image with a small Node proxy script from a ConfigMap, not nginx: no new image or dependency; a pod sysctl net.ipv4.ip_unprivileged_port_start=0 lets the non-root node user bind 443.
- Step 2 logs in with the first-admin invite (?invite=<token>): chronicle's report requires analytics:read, which a login gets only by redeeming that invite, created when the domain is set.
- The golden path takes S-0006's namespace block and session_jwt capture verbatim (MS-0037), so the two branches merge on identical lines.
- Shared paths with S-0007 (MS-0032), S-0008 (MS-0033), S-0010 (MS-0034) so they can start; told S-0025 about the one step added to scripts/kluster-deploy.sh (MS-0036).
- Operator answered TH-0047 with option 1: fix tower in S-0017. T-0137 makes tower's portcullis registration add only `_admin` when portcullis already configures the tenant, and the whole tenant otherwise. T-0110 now waits for T-0137 too.
- Running make install in the worktree: the only test tier (scripts/test.sh) runs every npm project and stops on a project with no node_modules (I-0010).
- T-0138: registration tries the narrow `_admin` add first and falls back to the whole tenant only when signet rejects the patch itself (not on gRPC 1, 4, 7, 14, 16). Signet's error code for a missing parent is unknown here, so the fallback is keyed on what is not a patch rejection; a wrong fallback still fails rather than regressing a fresh tenant.

- The golden path itself cannot run from the story's agent: the namespace kubeconfig reaches only s-0017, not dex or postgres. The same chain is proven from inside s-0017 with a scratch driver run in tower's pod.
