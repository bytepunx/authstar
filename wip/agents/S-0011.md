## Decisions

- **The planner's eight tasks stand as written.** I reviewed them against the four criteria and found nothing to change. The operator's answer on TH-0010 kept the plan (D-0018).
- **Layers.** Layer 1 holds T-0027, T-0028, T-0029, T-0030, and T-0032, which share no path. Layer 2 holds T-0031, T-0033, and T-0035:
  - T-0031 waits for T-0029, which writes `upstream-error.ts`.
  - T-0033 waits for T-0032, which writes `SubmitButton.svelte`.
  - T-0035 waits for T-0027, T-0028, and T-0029, because its e2e test exercises all three.
- **Task sub-agents do not run `flai test`; I run it once per layer.** The one test tier runs every project's suite whatever the paths, which takes about 8 minutes. Steward's e2e also binds fixed ports and reuses a running server (I-0010). Parallel sub-agents running it at once would collide. This departs from `delegation.md`, which has each task sub-agent run its own tests.
- **Web's Playwright e2e is in no test tier.** `web`'s `npm test` leaves out `test:e2e`, so neither `flai test` nor the close-out runs `web/e2e`. T-0035's spec and the e2e Done-when lines of T-0032 and T-0033 are checked with `npm run test:e2e` in `web`, run once by hand. This departs from `delegation.md`; flai has no tier to run it through.
- **An unreachable tower or keep is not mapped to 502.** `fetch` rejects with a `TypeError` before the clients build a request error, and `upstream-error.ts` cannot tell that from a bug. Such a failure still lands on the root `+error.svelte` as "Something went wrong", not SvelteKit's default page, so criterion 3 holds. Mapping it to 502 means wrapping `fetch` in `web/src/lib/server/clients/`; `keep.ts` is S-0008's claim, so it is left for a later story.
- **Layer 1 review.** `$app/state` needed a vitest alias and a stand-in module for the component tier, `web/vitest.components.config.ts` and `web/spec/fixtures/app-state.ts`, added to T-0028's touches. T-0029 left the organization invite action alone, since it was already in a try. It put the applications/new load case in `applications-list.spec.ts`, because `applications-create.spec.ts` is not in its touches. `SubmitButton.svelte` exports `pendingSubmit` from its module script for T-0033 to reuse. I-0016 duplicates I-0013, which S-0008 recorded on its branch.
- **Native modules were built by hand in this worktree.** npm 12 blocks install scripts by default, so `make install` leaves farmhash unbuilt in herald, keep, and tower, and their suites fail. I ran farmhash's `prebuild-install` in each, and recorded the defect as an issue.
