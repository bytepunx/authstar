## Decisions

- Kept the planner's five tasks and their plan unchanged. Their touches and after match the code layout the Notes describe.
- Layer 1: T-0048 (lookout) and T-0049 (portcullis emitter). They share no path and neither reads the other's output, so they run together.
- Layer 2: T-0050 (callback and logout dispatch). It waits for T-0049, whose emitter and state field it calls, and it shares `authstar-middleware/tests/integration_tests.rs` with T-0049.
- Layer 3: T-0052 (golden path) and T-0053 (overview, operator docs). Both wait for T-0048 and T-0050, so they describe and exercise what is built. They share no path.
- Criterion 3 cannot be checked here. Step 6 cannot read chronicle's report until S-0017 (I-0007, D-0019), and no local kluster runs: the only kubectl context is a remote cluster, which is left alone. Asked on TH-0043. T-0052 waits on the answer.
- T-0049: `build_state` reads `lookoutUpstream` from the bundle itself, as it does `webUpstream`, so its callers don't change. The state carries an `AnalyticsEmitter`. Each post has a fixed 2s timeout, and the bundle key's `timeout` is not used.
- T-0048: lookout takes its server allowlist as a route-plugin option, not a decorator, to stay out of `fastify-augment.d.ts`. `idp` is optional on logout, signup, and invite events. `reason` is optional on `login-failed`.
- T-0050's failure mapping in `callback.rs`:
  - State mismatch: `state_mismatch`.
  - Missing PKCE cookie: `pkce_missing`.
  - Missing `code`, a token exchange that is non-2xx or errors, or a malformed token body: `token_exchange_failed`.
  - Userinfo that is non-2xx or errors: `userinfo_failed`.
  - No `email` or no `sub`: `incomplete_profile`.
  - Unknown host or tenant, a suspended tenant, an unknown provider, no identity-hash key, a failed tower resolution, no candidate hashes, or no or failed session signing: nothing is emitted. These are not login outcomes at a known provider, or they are server faults.
- T-0050: `signup-completed` is emitted beside `login-succeeded` once the session is signed, so every counted signup is a counted login. Logout sends `identityHash` only when the cookie verifies. It repeats the gate's small session check, because `gate.rs`'s helper is private and outside the touches.
- `design/system/overview.md` split with S-0008 (MS-0011): S-0010 changes only portcullis's and lookout's rows, the analytics edge, and the State section.
