The fifth copy follows the operator's four-copies answer on TH-0026 (D-0021). T-0077 widened to chronicle's chart entry and docs/operators/chronicle-configuration.md and index.md.
- Plan: layer 1 T-0054 (ADR); layer 2 T-0056, T-0069, T-0072, T-0075, T-0171, which share no path and run together, waiting for the ADR's module shape; layer 3 T-0077 (chart, waits for all five services, since dropping the variable earlier breaks their calls to tower) and T-0172 (harness, waits for T-0069 and T-0171); layer 4 T-0079 closes I-0001 after T-0077 and T-0172.
- ADR-0113: node:https-backed fetch with the Workload API's trust bundle as CA and a SPIFFE trust-domain checkServerIdentity, not an undici Agent: no new runtime package, and SvelteKit's handleFetch keeps one Response class. Trust domain is read from the service's own SVID, so no new configuration. The flai assigned number 0113, not the planned 0111, which S-0006 took.
- One reference module, cert helper, and spec, written once under bin/S-0015/reference/ and copied into each service, so the five copies stay identical.
- Task sub-agents do not run `flai test`: the tier runs every project's suite (I-0010, 8m a run here) and steward's e2e uses fixed ports, so five parallel runs would collide. I run it once per layer on the layer's paths.
- Cost of delay set to penalty_per_week 200, the planner's recommendation the operator accepted on TH-0013.
- Criterion 1 verified three ways: each service's tower-tls.spec.ts (real TLS handshakes, plain fetch refused); `helm template chart` renders no NODE_TLS_REJECT_UNAUTHORIZED; and kluster golden path at 820d279 passed keep's and chronicle's https calls to tower without it. Herald's harness bundle uses http:// for tower, so its path is plain fetch there.
- Recorded I-0028: golden path's herald send-and-verify failed with an RSA OAEP error on S-0015's first checks run and passed on rerun at the same commit, as S-0013's and S-0017's did. It is not S-0015's change.
