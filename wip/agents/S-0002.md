# S-0002 Root CI and Make targets run every component's tests

## Context

Second story of E-0001. Per-component CI was orphaned by the monorepo move (GitHub Actions ignores `.github` below the root) and the root scripts were template stubs.

## Current state

All five criteria ticked, four tasks done. `story/S-0002` (stacked on `story/S-0001`, pushed, draft PR bytepunx/authstar#1) carries the root CI workflow, the chart manifest check, the ported npm publish workflows, the scripts, the Make targets, and the contributor guide; every per-component `.github` folder is removed. `make install && make test` passed on this host on 2026-10-21. GitHub refused to run the workflows because of the organization's billing (I-0003). Awaiting acceptance.

## Next steps
1. Operator: fix Actions billing (I-0003), then re-run the checks on bytepunx/authstar#1.
2. Operator: accept S-0001, then S-0002.

## Decisions

- `story/S-0001` is merged into this branch because S-0001 is in review and this story edits files it changed; when S-0001 is accepted first the merge is a no-op.
- The integration test tier stays out of CI for now, as the old workflows chose, because it needs Docker on the runner; `make integration` runs it locally.
- Image tags are `latest` and the commit SHA; semver image tags wait for the release convention to name component tags.
- The chart's signet-manifest check is ported to `.github/workflows/chart-manifest.yml`, path-filtered to `chart/**`, rather than dropped.
- The two npm publish workflows are ported to the root with `clients/typescript` paths and the same file names, so re-registering the npm Trusted Publisher against `bytepunx/authstar` is the only step left to publish from here. release-please is not ported: its package paths and manifest would need rewriting for the monorepo, and the release convention in `git.md` says `flai release` will cut releases.
- `scripts/test.sh` runs each project's whole `npm test` (behavior and e2e) because that is what the old CI ran and the e2e tiers need nothing external.
