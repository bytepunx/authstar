# S-0006 Serve GET /_authstar/me/subscription for the subscription-status widget

## Context

E-0002. The widget web ships has no server behind it: neither keep nor portcullis implements the `/me/*` family ADR-0071 defined. This story adds keep's route and portcullis's gated forward.

## Current state

Criteria 1, 2, and 4 are ticked. Criterion 3 waits on TH-0031. The close-out passed at bb1c2f1. The branch has since gained one commit, c6c418a, the I-0007 bump. The worktree is clean.

The operator deployed S-0006 into kluster namespace `s-0006` (bb1c2f1), and I ran the golden path there (T-0132's `KLUSTER_NAMESPACE`/`KLUSTER_TOKENS`, flai's k3d kubeconfig):

- Steps 1–4 pass.
- **Step 4b reaches keep through portcullis, and keep answers 403.** Keep cannot verify the internal JWT: `perTenantJwksKeyProvider` fetches `https://authstar.<domain>/.well-known/jwks.json`, which the harness cannot serve in-cluster, and `acme` has no domain (I-0007, D-0019). S-0017 fixes that gap.
- Step 5 (herald decryption) fails on the known signet key issue, unrelated to S-0006.

## Decisions

- `story/S-0001` is merged into this branch because the golden-path step lives in `integration/`, which only S-0001 carries until it is accepted.
- With more than one subscription for an account, the route reports a live one before an ended one, newest first; story keep/006 speaks of one subscription and does not say.
- Portcullis reaches keep over the plain HTTP client, as ADR-0095 chose for webhooks, not SPIFFE mTLS as ADR-0071 says, because the mTLS client is tower-only today. Raised for the operator as a thread rather than changed here.
